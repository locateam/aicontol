AIContol — скилл для разработки с ИИ-агентом, в которой ты проверяешь результат на каждом этапе. Агент исследует задачу, предлагает решения, пишет код и запускает проверки. Ты решаешь, что строить, правишь документы и код, одобряешь следующий шаг.

Версия 1.0.0. Выполненные статические проверки описаны в [отчёте](evals/REPORT.md). Поведение агента в отдельных сессиях пока не проверялось.

## Установка

Нужны [Node.js](https://nodejs.org/) версии 22.20 или новее и Git:

```sh
npx skills add locateam/aicontol
```

[Skills CLI](https://skills.sh/docs) предложит выбрать агента и установит скилл в текущий проект. Для глобальной установки в Codex:

```sh
npx skills add locateam/aicontol --skill aicontol --global --agent codex
```

В интерфейсе скилл называется AIContol, техническое имя для установки и вызова — `aicontol`.

Посмотреть, что CLI находит в локальном репозитории, без установки:

```sh
npx skills add . --list
```

Для ручной установки скопируй весь пакет в каталог скиллов своего агента под именем `aicontol/`. Сохрани `SKILL.md` вместе с вложенными папками. Если агент требует перезагрузить список скиллов, сделай это после копирования.

## Как пользоваться

Выбери AIContol в списке скиллов или напиши:

> Используй $aicontol для этого проекта. Начни с рабочего соглашения. Я хочу сам проверять каждый модуль.

Сначала агент согласует с тобой процесс, разрешённые действия, язык и размер проверяемых частей. Сама установка не даёт разрешения начать работу над проектом.

## Порядок работы

1. Договориться о процессе, самостоятельности агента и фразе для изменения плана.
2. Вместе разобраться в проблеме, пользователях и объёме задачи.
3. Выбрать стек, архитектуру и инженерные правила.
4. Собрать документацию, решения и состояние проекта.
5. Описать контракты модулей, архитектурные наброски и порядок работы.
6. Провести небольшие эксперименты там, где есть сомнения в реализуемости.
7. Реализовать согласованные части, проверить их и исправить ошибки.
8. Проверить систему целиком и принять результат.

Перед следующим этапом ты проверяешь результат. Эксперименты и реализация проходят проверку по каждому модулю или согласованной части. В маленькой задаче этап может занять несколько строк; объединить проверки можно по договорённости. В существующем проекте можно зачесть уже сделанную работу после твоего одобрения.

Эксперимент отвечает на вопрос о риске, реализация даёт рабочее поведение, которое предстоит поддерживать. Проверки идут во время разработки и в конце.

## Если план нужно поменять

По умолчанию агент предложит фразу `PIPELINE OVERRIDE:`. После её согласования можно дать конкретное указание:

> PIPELINE OVERRIDE: пропусти эксперимент для M03 и начни его согласованную реализацию.

Агент запишет, что пропущено и каких подтверждений теперь нет. Можно просто сказать «стоп» или изменить процесс обычными словами. Фраза нужна для удобства, это не пароль.

Скилл задаёт рабочее соглашение. Он не гарантирует послушание модели и не отменяет ограничения среды. Для публикации, деплоя, расходов и передачи данных наружу нужны соответствующие разрешения. Другие скиллы можно использовать в рамках договорённости; конфликтующие правила процесса нужно согласовать отдельно.

## Как сделать установку через npx

Опубликуй весь пакет в `locateam/aicontol`: `SKILL.md` должен лежать в корне. В опубликованной версии нужны `name: aicontol`, описание и все файлы, на которые ссылаются инструкции. Репозиторий должен быть доступен устанавливающему; для открытого распространения проще сделать его публичным.

Отдельный npm-пакет и `package.json` не нужны: `npx` запускает Skills CLI, а тот скачивает скилл с GitHub. После публикации проверь обнаружение:

```sh
npx skills add locateam/aicontol --list
```

Затем попробуй команду установки выше. По [FAQ Skills](https://skills.sh/docs/faq), скилл появляется в каталоге skills.sh через установки, учтённые телеметрией CLI. Один бейдж не регистрирует скилл и не создаёт счётчик установок.

## Изменения и проверки

Правила процесса находятся в основном файле и справочниках, стиль общения — в отдельном файле, заготовки документов — в шаблонах. После изменений проверь метаданные и локальные ссылки, затем запусти подходящие [поведенческие сценарии](evals/SCENARIOS.md) в тестовой папке. Запиши среду и модель, входной запрос, действия агента и результат. Статическая проверка не доказывает, что агент соблюдает контрольные точки.

При редактуре README ориентировались на [Humanizer](https://github.com/blader/humanizer). Для работы AIContol он не нужен.
